# uuHalo AI 架构方案

> 2026-06-19 凌晨讨论总结 · CC 与 uu 共同梳理

## 最终路径：API 路线

**不走 CC（Claude CLI），走 Claude API + 自建网关。**

理由：CC 的功能（记忆、时间轴、日记、prompt 管理）与网关架构大量重叠，接 CC 会变成两个重复的大脑。走 API 把网关作为唯一的 AI 调度层，架构更干净。

## 架构总览

```
uuHalo 前端 (React)
    ↓ HTTP/WebSocket
网关服务 (VPS)
    ├─ Prompt 模块管理（人格、输出规范、交互规则）
    ├─ 记忆引擎 mem0（原子抽取、语义搜索、情绪分析）
    ├─ 日历层级摘要（日/周/月自动生成）
    ├─ 冷启动系统（新窗口不丢数据、自动加载上文）
    ├─ 工具定义 & 执行（按需加载，省 token）
    ├─ 管理面板（移动端可操作）
    └─ 请求重建引擎（token 控制）
    ↓ HTTP
Claude API (Anthropic)
    ↓ tool calls 返回
网关服务 → 执行工具 → 读写数据

项目后端 (同一 VPS)
    ├─ 日记 CRUD
    ├─ 记忆 CRUD
    ├─ 时间轴读写
    ├─ 共读/书架/笔记（未来）
    └─ 其他业务 API
    ↓
云数据库 (PostgreSQL / MySQL)
```

## 各层职责

| 层 | 做什么 | 不做什么 |
|---|--------|---------|
| **uuHalo 前端** | 页面渲染、用户交互、展示数据 | 不直接调 Claude API |
| **网关服务** | 接前端请求、管 prompt、调 Claude API、收 tool call、执行工具 | 不存业务数据（交给后端 API） |
| **项目后端** | 日记/记忆/时间轴/共读等业务 API | 不管 AI 对话逻辑 |
| **云数据库** | 持久化所有数据 | 不在 VPS 本地存数据 |
| **Claude API** | 理解、生成、判断何时调工具 | 不直接操作数据库 |

## VPS 角色

VPS 是**可替换的计算壳**：
- 跑网关服务 + 项目后端
- 存项目 git 仓库
- 数据全在云数据库，换 VPS = `git clone` + `npm install` + 配 `.env`，三分钟

不本地存数据、不存状态。关机删掉不丢任何东西。

## 工具调用流程

```
用户说"今天过得怎么样"
→ 前端发送到网关
→ 网关拼接 prompt + 上下文 + 按需加载的工具定义
→ 调 Claude API
→ Claude 判断需要调：查今日日记 + 查时间轴 + 搜记忆
→ 网关收到 3 个 tool call
→ 网关调项目后端 API：
    GET /api/diary/2026-06-19
    GET /api/timeline/2026-06-19
    GET /api/memories/recent
→ 结果返回 Claude
→ Claude 生成最终回复
→ 网关返回前端
```

## 按需加载工具 · 省 Token 策略

不是每次请求带全部工具。网关根据对话上下文判断：

- 普通聊天 → 只带基础上下文，不带工具
- 用户说"写日记" → 加载日记相关工具
- 用户说"共读" → 加载共读相关工具
- 改代码场景 → 加载文件操作工具

功能多不会导致 token 膨胀。

## 构建顺序

### 第一步：项目后端基础骨架
- 选框架（Node + Express/Fastify）
- 建数据库表（日记、记忆、时间轴）
- 写基础 CRUD API

### 第二步：网关服务
- 参考个人网关架构设计
- 搭 prompt 模块管理
- 接 Claude API
- 实现工具定义 & 执行

### 第三步：对接
- 每个后端 API → 对应的网关工具定义
- 不是一一对应：一个工具可能调多个 API

### 第四步：加功能
- 每加一个新功能：后端写接口 → 网关配工具
- 固定流水线，不额外增加架构复杂度

## 与 CC（cyberboss-app）的对比

| | CC 路线 | API 路线 |
|---|--------|---------|
| 依赖 | 需要跑 Claude CLI 进程 | 纯 HTTP API 调用 |
| 内存 | 吃 VPS 内存（Claude CLI） | 轻量 |
| 记忆/日记/时间轴 | CC 自带 | 网关自建 |
| 改代码能力 | 原生支持 | 需配文件操作工具 |
| 架构复杂度 | 网关 + CC 双重调度 | 网关唯一调度层 |
| 适合场景 | 需要文件系统操作的长 session | 陪聊 + 轻量工具调用 |
